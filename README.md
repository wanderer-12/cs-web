# CSP — Counter-Strike Prototype

浏览器里的 3D 第一人称射击游戏，目标是**手感像 CS**（不是画面像）。
纯客户端、零素材、运行时依赖只有 `three` 一个：单机 5v5 打 Bot，完整回合制 + 经济系统 + C4 攻防。

```bash
pnpm install
pnpm dev        # http://localhost:5174
```

> ⚠️ 必须用 `pnpm`（`npm` / `npx` 会被 `packageManager: pnpm@12.9.0` 拒绝：`Invalid name "npm" does not match "pnpm"`）。

| 项目 | 值 |
|---|---|
| 技术栈 | Vite 8.3.2 + TypeScript 7.0.2 + Three.js 0.186.1 + Vitest 5.0.3 |
| 运行环境 | Node v24.21.0 / pnpm 12.9.0（浏览器需支持 WebGL2 与 Pointer Lock） |
| 运行时依赖 | **1 个**（three）。物理、音频、UI、贴图全部自研 |
| 素材依赖 | **0 个**。贴图用 canvas 程序化生成，枪声用 Web Audio 合成 |
| 源码 / 测试 | 53 个 TS 文件 21845 行 / 14 个测试文件 6660 行 |
| 首屏体积 | **216.9 KB gzip**（three 133.3 KB + 游戏代码 82.8 KB + HTML 0.8 KB），预算 900 KB |
| 模拟频率 | 固定 128 Hz（`TICK_DT = 1/128`），渲染自适应帧率 |

## 0. 一键启动（Windows）

不想敲命令就用启动器（Windows 专用；macOS / Linux 仍用上面的 `pnpm dev`）：

| 入口 | 作用 |
|---|---|
| 桌面快捷方式 `CSP 人机对战` | 双击 = 开发模式直接开玩（指向 `启动游戏.cmd`） |
| `启动游戏.cmd`（项目根目录） | 同上，双击即玩 |
| `启动器菜单.cmd`（项目根目录） | 双击打开菜单：开发 / 生产 / 只构建 / 跑测试 / 改启动参数 |
| `launcher\start.cmd <模式> [选项]` | 命令行入口，模式 = `menu` `dev` `prod` `build` `test` `params`（模式可省略，只给选项时默认 `dev`） |

启动器会检查 Node / pnpm 版本、缺依赖时自动 `pnpm install`、端口被占时往后找空闲端口、**等 HTTP 真的应答之后再打开浏览器**，退出时停掉服务；
`prod` 模式会先比对 `dist/index.html` 与源码的修改时间，需要时才 `pnpm build`。

常用选项（跟在模式后面）：

| 选项 | 作用 |
|---|---|
| `-Port 5180` | 指定端口（默认开发 5174 / 生产 4173） |
| `-UrlParams "difficulty=expert&team=CT&seed=1234"` | 直接带上第 1 节的启动参数 |
| `-NoBrowser` | 不自动打开浏览器 |
| `-Reinstall` | 强制重装依赖 |
| `-DryRun` | 只打印环境诊断，不启动任何东西 |

`launcher\settings.txt` 保存默认启动参数（首次运行自动生成，可用记事本直接改）：

```ini
difficulty=normal
team=
seed=random
name=
stats=0
```

> 启动器只是包装 `pnpm`，不改变任何游戏行为。另外 `dist/index.html` **不能直接双击打开**（`base: './'` + ES module 会被 `file://` 的 CORS 拦住），必须走本地 HTTP 服务器 —— 这也是启动器存在的原因之一。

## 2. 玩法

* **5v5**：玩家 + 每队 4 个 Bot。子弹对队友无效（`friendlyFire` 关闭）。
* **MR12 赛制**：先拿 13 分获胜，最多 24 回合，第 12 回合后换边。
* **回合流程**：8 s 冻结时间（不能移动，可买枪）→ 20 s 购买时间 → 115 s 回合 → 回合结束 5 s 结算。
* **经济**（CS 数值）：
  * 起始 800，上限 16000；胜 3250，靠炸弹获胜 3500；
  * 败方 1400 + 连败 ×500（最多累计 4 连败，上限 3400），埋包成功即使被拆也给 800；
  * 埋包 +300、拆包 +300。
* **C4**：T 携带者进 A/B 点位按住 `E` 3.2 s 埋包，炸弹 40 s 后爆炸；CT 对炸弹按住 `E` 拆包 5 s（有拆弹器）/ 10 s（无）。
* **购买菜单**：17 把武器 + 3 件装备（护甲 650 / 护甲+头盔 1000 / 拆弹器 400，仅 CT）。

武器表现全部按 CS 数值建模：步枪 AK-47 / M4A4 / M4A1-S / Galil / AWP / SSG08，冲锋枪 MP9 / MAC-10 / P90，手枪 Glock / USP / P250 / Five-seveN / Deagle，霰弹枪 Nova，以及刀、C4（共 17 件）。
每把枪都有**固定可背的弹道图案**（前 10 发的偏移表 + 种子化随机）、独立的头部/胸腹/胃/腿判定、护甲吸收与穿透。

## 3. 「CS 手感」是怎么落地的

计划里拆出的 7 个要素，逐条对应实现：

| # | 要素 | 实现 |
|---|---|---|
| 1 | **移动** | 自研 Quake 系运动模型：地速 250、走 130、蹲 85、空中加速保留但限速 30、连跳保速；1 米 = 52.49 单位，重力 800、起跳冲量 268.3 |
| 2 | **枪口稳定** | 速度→散布曲线（`computeInaccuracy`：移动项按 `(speed/250)^1.25`，空中锥角独立给定），必须急停才准 |
| 3 | **弹道** | 每把枪 30 发固定偏移表 + 种子化伪随机，前 10 发可背 |
| 4 | **命中判定** | 头 / 胸腹 / 胃 / 腿分离胶囊体；腿和无头盔爆头无视护甲 |
| 5 | **反馈** | 枪口火焰、抛壳、弹孔贴花（上限 192 个）、命中提示音、击杀播报、血迹、曳光弹、着弹火花、尘土、**擦耳弹啸**（`whizzBy`：路径离耳朵 64 单位以内的子弹发 `whizz` 事件，音量随最近距离缩放） |
| 6 | **节奏** | 完整回合计时器 + 经济 + 买枪菜单 + 炸弹攻防 |
| 7 | **视角** | 相机层可叠加：走路摆动（bob）、开枪后坐视角偏移（punch，水平 ±0.5 / 垂直 ±0.45 弧度）、落地下沉、开镜变焦 |

**明确不做**：自动回血、无限冲刺、载具、瞄准镜呼吸。

### 三个把「手感」做对的细节

* **急停是有代价的**：`stopSpeed = 80`，摩擦 5.2。这个数字很关键——摩擦的每 tick 下限是 `80 × 5.2 × dt`，必须小于蹲行加速 `5.5 × 85 × dt`，否则蹲姿玩家会被摩擦钉在原地（本项目真的踩过这个坑，见 §6）。同时 250 → 0 刹停约 0.4 s，仍然「脆」。
* **连跳保速不增益**：落地那一 tick 的摩擦亏损（250 u/s 时 10.2）≈ 地面加速补回（10.7），加速度在 250 处夹紧，所以连跳恰好停在 250；把落地摩擦清零会产生 surf 式 400+ u/s 的失控。
* **视角抖动不进准心**：`punch` 只作用于相机，`aimDirection()` 才把它叠加进射击方向——否则后坐会永久污染 `state.yaw`（人机对战里 Bot 就是这么治好的）。

## 4. Bot AI

* 难度 4 档，每档只调 4 个参数：`reactionTime`（反应时间）、`aimError`（瞄准误差）、`sprayControl`（压枪）、`preaimQuality`（预瞄质量）。每个 Bot 出生时再乘一个 0.8–1.2 的随机系数，所以同一档也有强弱差异。
* **感知**：射线可见性检查 + 目标记忆 6 s（记住最后已知位置，会追过去）+ 听觉（脚步、枪声、埋包/拆包声）。受到攻击会撤退。
* **目标选择**：五级级联——1) 任务（埋/拆/守点）2) 交火 3) 保命 4) 调查声音 5) 推进/守点。埋包后 CT 转为「retake」、T 转为「守炸弹」。
* **导航**：`de_dust2_lite` 手工烘焙的 **309 个节点**导航图（含 A 大、B 洞、中路、猫道、A/B 点内部节点），`findPath` + 路径平滑 + 卡住检测（连续 24 tick 位移 < 0.5 单位就尝试左右探路脱困，并重挂路径）。
* **开火条件**（`shouldFire`）是严格的：弹药/换弹/开镜时间检查 → 反应时间已过 → 有可见敌人 → 瞄准角误差在胸宽锥角内 → 散布不超过阈值 → 在有效射程内 → 伤害 > 0 → 不误伤队友。所以 Bot 不是「看见就突突」，而是必须真正瞄上。
* **身体分离**：Bot 会朝共享的目标节点收拢，所以每 tick 有一遍 `separatePlayers`——水平距离小于两个半径的存活角色互相推开（单 tick 最多 8 单位，会把角色推进墙里的推动整条丢弃，玩家永不被推）。否则一整队会叠在同一个坐标上。

## 5. 性能报告

全部数字在本机（Node 24 / Windows）实测，脚本可复现：`pnpm vitest run tests/perf.spec.ts`。

### 模拟（逻辑）

| 指标 | 预算 | 实测（两次独立运行） |
|---|---|---|
| 10 人满员回合 `Match.tick` 平均 | < 0.60 ms | **0.42 – 0.53 ms**（p50 0.36–0.48 / p95 0.84–0.94 / max 2.96–15.2，2560 样本） |
| 有开火的那一 tick 平均 | — | **0.70 – 0.82 ms**（18/2560 tick 有射击，p50 0.54–0.65） |
| 单人 `stepMovement` | — | **0.0023 – 0.0026 ms**；外推 10 人 × 128 Hz = **0.023 – 0.026 ms/tick** |
| `nav.findPath`（CT 出生点 → A 点） | — | **0.87 – 1.03 ms**（p95 1.27–1.37），只在换目标时调用，不是每 tick |
| `nav.nearestNode` | — | **0.0007 – 0.0013 ms** |

一个回合 20 s 窗口内：18 发子弹、13 次命中、2560 tick。

**结论**：模拟预算 0.6 ms/tick（128 Hz 下占用 7.7% 的一帧）有充足余量——满员回合均值 0.42–0.53 ms，开火帧 0.70–0.82 ms，导航寻路不在热路径上。

### 渲染

渲染帧率无法在无浏览器环境自动测量（没有 Playwright），预算按计划设为：**draw calls < 80、三角形 < 300k**。
地图几何按 `(材质, 色调)` 合批（`MapGeometry.ts`：约 140 个轴对齐盒子合成十余个 mesh），天空是一个 9000 半径的球面。
在游戏里按 `F3` 或加 `?stats=1` 可看到实时的 `drawCalls / triangles / mapDrawCalls / mapTriangles / programs / textures`。

## 6. 开发中修掉的真实 bug（都有回归测试）

手感类项目的 bug 往往表现为「说不出来哪里不对」，这几条是写 `tests/movement.spec.ts` 时被 15 条物理测试逼出来的：

1. **蹲行走不动**：摩擦的每 tick 下限 `stopSpeed(100) × 5.2 × dt = 4.06` 大于蹲行加速 `5.5 × 85 × dt = 3.65`，速度被钉在 3.65 u/s——蹲着移动 24 tick 只前进 0.57 单位。改成 CS:GO 的 `stopSpeed = 80` 后正常。同一条 bug 也解释了 Bot 在狭路「踱步」的怪现象。
2. **落地吸附把玩家瞬移到天花板顶面**：`sweepExpanded` 在扫描起点就已重叠时返回 `hit=true, fraction=0, normal=(0,1,0)`，地面解算把它当「踩到地面」，于是把脚底吸到那块刷子的**顶面**——低矮天花板下实测 `y` 从 0 跳到 400，玩家站到了天花板上。加了 `GROUND_SNAP_MAX_RISE = 1.0` 上限。
3. **连跳掉速到比走路还慢**：落地 tick 除摩擦外还乘 `vel *= 0.94`，每跳净亏 15 u/s，空中 30 u/s 的加速上限补不回来，实测 3 秒跳跑峰值只有 52.7 u/s。删掉后连跳稳定在 250。
4. **Bot 不开枪**（三个独立根因，都影响人机对战的可玩性）：
   * 没有任何代码把 `cmd.yaw/pitch` 写进 `state.yaw/pitch`（只有相机在动），于是所有 Bot 的瞄准方向永远停在出生角，且后坐（punch）永不衰减、永久污染准心 —— 修复后 Bot 才真正「转身面朝敌人」。
   * 所有 Bot 共用同一个 `InputCommand` 对象，`think` 只写自己决定改的字段，于是每 tick 最后一个 Bot 决定了全队的按键和视角；`shouldFire` 拿 `cmd.yaw` 做夹角检查时量到的是别人的准心 —— 改为每个 Bot 一个 command 对象。
   * 卡住计数器写反了（移动时累加、被挡住时清零），Bot 贴着墙永远报告 `stuck=0`，再加「脱困时只按一侧方向」被转向逻辑的另一侧抵消，会出现 `forward+left+right` 且速度为 0 的永久冻结 —— 两处都修了。
   * 另外：走路脚步声每 tick 触发「去调查声音」，导致埋包后的 CT 全队 40 s 都不去拆包 —— 调查分支现在只在「不需要移动的任务」上生效。

### 与 `PLAN.md` 的差异（如实记录）

| 计划 | 实际 | 原因 |
|---|---|---|
| `public/maps/de_dust2_lite.json` | `src/world/maps/de_dust2_lite.ts` | 地图数据用 TS 模块更早得到类型检查与构建期校验；没引入 JSON 加载器 |

| `tests` 用 Playwright 做启动/开火冒烟测试 | **没有 Playwright** | 没有可用的浏览器自动化环境，改为纯逻辑 Vitest + 人工开页面验证渲染 |

## 9. 已知限制

* **投掷物（闪光/烟雾/HE）未实现**：`weaponDefs` 里没有手雷定义，买枪菜单的投掷物栏是空的，`slot4/5` 没有内容。这是当前最明显的缺口。
* **联机未实现**：`src/net/` 只有协议编解码、插值缓冲、回滚历史、预测簿记这些**已实现并测试**的部分，WebSocket 传输与服务器还没写；单机模式完全不依赖它（见 `src/net/Net.md`）。
* **Bot 之间只做「推开」而不是真正的身体阻挡**：`Match.separatePlayers` 每 tick 把水平距离小于两个半径的存活角色各推开一半（单 tick 上限 8 单位，会把角色推进墙里的推动整条丢弃，玩家本人永不被推），所以不会再看到几个人叠在同一个坐标上，但这仍不是 CS 那种「贴住对方就过不去」的硬阻挡，拥挤时会有轻微推挤感。
* **导航图有两处绕路**：CT 出生点北墙附近的车道节点被墙带吞掉（`nearestNode` 判为实心而丢弃），导致 CT 去 B 点会多绕一段。
* **T 队 AI 偏「正面强冲」**：Bot 会集体压 A 大被 CT 架枪团灭，战术多样性不足（平衡问题，不是故障）。
* **渲染性能与画面只能人工确认**：自动化环境里没有 GPU/浏览器，`drawCalls`、三角形数、贴花上限都需要玩家按 `F3` 自查。
* **启动器只在 Windows 上可用**：`launcher\play.ps1` 是给 Windows PowerShell 5.1 写的脚本，三个 `.cmd` 入口靠双击使用；macOS / Linux 直接用 `pnpm dev`（见第 0 节）。

## 10. 下一步

1. 手雷三件套（闪光/烟雾/HE）+ 投掷物 UI。
2. 三期联机：`Transport`（WebSocket）→ 服务器 128 Hz 权威循环 + 20 Hz 快照 → 客户端预测与延迟补偿接线。
3. 给导航图烘焙加几何检查（现在只检查悬空/非互惠/孤立，不检查连线是否穿墙），并把 CT 出生点北墙的节点补救回来。
4. Bot 战术：默认进攻点分配、分散包夹、假打转点。
