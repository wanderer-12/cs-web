# CSP — Counter-Strike Prototype

浏览器里的 3D 第一人称射击游戏，目标是**手感像 CS**（不是画面像）。
纯客户端、零素材、运行时依赖只有 `three` 一个。三种玩法：**经典模式 5v5 打 Bot**（完整回合制 + 经济系统 + C4 攻防）、**单挑模式 1v3**（小图、三阶段武器、先到 17 回合）、**局域网 1v1**（一台机器在浏览器里当服务器，另一台填 IP 连进来）。

```bash
pnpm install
pnpm dev        # http://localhost:5174
```

> ⚠️ 必须用 `pnpm`（`npm` / `npx` 会被 `packageManager: pnpm@12.9.0` 拒绝：`Invalid name "npm" does not match "pnpm"`）。

| 项目 | 值 |
|---|---|
| 技术栈 | Vite 8.3.2 + TypeScript 7.0.2 + Three.js 0.186.1 + Vitest 5.0.3 |
| 运行环境 | Node v24.21.0 / pnpm 12.9.0（浏览器需支持 WebGL2 与 Pointer Lock） |
| 运行时依赖 | **1 个**（three）。物理、音频、UI、贴图全部自研 |
| 素材依赖 | **0 个**。贴图用 canvas 程序化生成，枪声用 Web Audio 合成 |
| 源码 / 测试 | 65 个 TS 文件 29215 行 / 20 个测试文件 10237 行（532 条测试全绿） |
| 首屏体积 | **237.1 KB gzip**（three 133.5 KB + 游戏代码 102.9 KB + HTML 0.8 KB），原始 868.4 KB，预算 900 KB |
| 模拟频率 | 固定 128 Hz（`TICK_DT = 1/128`），渲染自适应帧率 |

## 0. 一键启动（Windows）

不想敲命令就用启动器（Windows 专用；macOS / Linux 仍用上面的 `pnpm dev`）：

| 入口 | 作用 |
|---|---|
| 快捷方式 `CSP 人机对战.lnk`（项目根目录） | 双击 = 开发模式直接开玩（指向 `启动游戏.cmd`；这个 `.lnk` 是**本机文件**，已在 `.gitignore` 里，不会进版本库） |
| `启动游戏.cmd`（项目根目录） | 同上，双击即玩 |
| `启动器菜单.cmd`（项目根目录） | 双击打开菜单：开发 / 生产 / 只构建 / 跑测试 / 改启动参数 |
| `launcher\start.cmd <模式> [选项]` | 命令行入口，模式 = `menu` `dev` `prod` `build` `test` `params`（模式可省略，只给选项时默认 `dev`） |

启动器会检查 Node / pnpm 版本、缺依赖时自动 `pnpm install`、端口被占时往后找空闲端口、**等 HTTP 真的应答之后再打开浏览器**，退出时停掉服务；
`prod` 模式会先比对 `dist/index.html` 与源码的修改时间，需要时才 `pnpm build`。

开游戏时它还会**自动拉起局域网中继**（`server/lan-relay.mjs`，端口 5175）并打印本机的局域网地址：

```text
局域网中继: 已启动（端口 5175）
局域网 IP : 192.168.1.23
联机地址  : http://192.168.1.23:5174/?join=1
```

朋友在同一个 WiFi 下打开那个联机地址就进房间了（见第 3 节）。中继是启动器拉起来的子进程，关掉启动器窗口它会一起停。

常用选项（跟在模式后面）：

| 选项 | 作用 |
|---|---|
| `-Port 5180` | 指定端口（默认开发 5174 / 生产 4173） |
| `-UrlParams "difficulty=expert&team=CT&seed=1234"` | 直接带上第 1 节的启动参数 |
| `-NoBrowser` | 不自动打开浏览器 |
| `-Reinstall` | 强制重装依赖 |
| `-DryRun` | 只打印环境诊断，不启动任何东西 |

`launcher\settings.txt` 保存默认启动参数（首次运行自动生成，可用记事本直接改）：

```ini
difficulty=normal
team=
seed=random
name=
stats=0
```

> 启动器只是包装 `pnpm`，不改变任何游戏行为。另外 `dist/index.html` **不能直接双击打开**（`base: './'` + ES module 会被 `file://` 的 CORS 拦住），必须走本地 HTTP 服务器 —— 这也是启动器存在的原因之一。

## 1. 操作

| 操作 | 键位 | 说明 |
|---|---|---|
| 移动 | `W` `A` `S` `D` | 后退/侧移有 0.92 速度系数（CS 的 backpedal 惩罚） |
| 走（静步） | `Shift` | 130 u/s，脚步声小、精度接近站定 |
| 蹲 | 左 `ALT` | 85 u/s，精度最高，必要高度 54；`C` 也能蹲（**不用 `Ctrl`**，见下） |
| 跳 | `Space` | 自动连跳开启（落地瞬间按住空格会自动起跳） |
| 开火 / 副功能 | 左键 / 右键 | 右键 = AWP 开镜、步枪装消音器（M4A1-S）；刀也能开火（挥砍） |
| 换弹 | `R` | |
| 使用（埋/拆包、换枪） | `E` | 站在炸弹点上按住埋包，CT 对着 C4 按住拆包；站在掉落的枪上按 `E` 换到手上 |
| 丢弃当前武器 | `G` | 掉在脚下，弹匣里剩几发就带走几发 |
| 切枪 | `1` `2` `3` `4` `5` | 主武器 / 副武器 / 刀 / C4 /（投掷物位未实现）；刀不耗弹药，可反复挥砍 |
| 购买菜单 | `B` | 菜单里点选或按数字键；`Tab` 在「分类键」和「购买键」间切换；`[` `]` 换分类 |
| 记分板 | `Tab` | 按住查看 |
| 暂停 | `Esc` | 释放鼠标指针 |
| 性能信息 | `F3` | 打印 `draw calls / triangles / simMs / fps` 等 |

鼠标灵敏度默认 2.2（`InputSystem.sensitivity`），开镜有独立的缩放灵敏度。

### 为什么蹲伏不是 `Ctrl`

这是浏览器游戏，`Ctrl+W` 关标签页、`Ctrl+D` 收藏、`Ctrl+R` 刷新、`Ctrl+A` 全选 —— 这些组合**任何网页都无法拦截**。而 CS 的蹲伏就是 `Ctrl`，蹲着走位等于一直按着 `Ctrl` 按 `WASD`，随手就把这一局弄没了。所以默认蹲伏改成**左 `Alt`**（`DEFAULT_BINDINGS.crouch.code === 'AltLeft'`，备选 `KeyC`），`Ctrl` 上不绑任何动作（`DEFAULT_BINDINGS` 里没有 `Control*`，`tests/input.spec.ts` 会断言这一点）。`C` 保留为备用键是有原因的：`Alt+Tab` 是操作系统级组合，页面拦不住，习惯用 `Alt` 的人偶尔会不小心切出窗口，这时 `C` 可以直接蹲。同理，蹲着按 `Tab` 看记分板也可能触发窗口切换，按一下 `Alt` 再松开即可。

其余会被浏览器抢走的键（`Tab` 焦点环、`Space`/方向键滚动、`F1`、`/`、`'`）在 `InputSystem.attach()` 里统一 `preventDefault()`（`BROWSER_HOGGED_KEYS`，含自动重复；`F5`/`F11`/`F12` 不在此列，因为浏览器不允许页面拦截它们）。判定只在事件目标不是输入框时生效，所以启动器里输入玩家名仍然正常。

### 丢掉和捡起枪

* `G` 把手上那格掉在脚下（拿着投掷物/C4 时丢主武器），**弹匣里剩几发就带走几发**，捡回来还是那几发。每回合开始清空地面，所以扔枪换不了经济。
* **空槽自动捡**：走过一把枪、对应槽位（主/副）空着，会像走过炸弹一样自动捡起。
* **占用时必须按 `E`**：槽位被占着不会强行换枪（否则跑图会被一路换枪）；站在枪上按 `E` 才换，换下的枪掉在脚下。同一把枪上按 `E` 也能在主/副武器之间倒手。
* **1.5 s 冷静期**：刚丢下的枪不会被自己立刻吸回去（否则 `G` 看起来像坏了），这段时间按 `E` 可以马上捡回。
* 尸体（主 + 副两把）和队友丢的枪都会留在地上，同时最多 24 把；同一点上有多把枪时，优先「能填进空槽的那把」，其次「和手上同槽位的那把」，最后取最新掉落。
* HUD 会在够得着的枪上给提示：空槽是 `Pick up AK-47`，要换枪是 `Swap for AK-47`。
* 渲染上所有地面武器按**种类**合并成 `InstancedMesh`（每类最多 8 把、黄金角散开朝向），一回合地面上有几类枪就几个 draw call，见 `src/render/GroundWeapons.ts`。

### 启动参数

| 参数 | 取值 | 作用 |
|---|---|---|
| `?bot=` / `?difficulty=` | `easy` `normal` `hard` `expert` | Bot 难度（4 档） |
| `?mode=` | `classic` `duel` | 跳过主菜单直接开某种单机模式（经典 5v5 / 单挑 1v3） |
| `?join=` | `1`、`auto` 或 `主机IP[:端口]` | 直接以客机身份联机；`1` = 连上「打开这个页面的那台主机」 |
| `?team=` | `T` `CT` | 玩家所属阵营（默认随机；局域网里主机固定 T、客机固定 CT） |
| `?seed=` | 任意整数 | 固定随机种子（复现同一场比赛） |
| `?name=` | 字符串 | 玩家名 |
| `?stats=1` / `?perf=1` | — | 每秒在控制台打印一行性能数据 |

例：`http://localhost:5174/?bot=expert&team=CT&seed=1234&stats=1`

## 2. 玩法

主菜单里选模式（也可以直接用 `?mode=` / `?join=` 跳过菜单）：

| 入口 | 模式 | 规模 |
|---|---|---|
| 单挑模式 · 1v3 人机 | `duel` | 你 1 人 vs 3 个 Bot，小图 |
| 经典模式 · 5v5 人机 | `classic` | 你 + 4 Bot vs 5 Bot，`de_dust2_lite` |
| 创建房间 / 加入房间 | `duel` | 局域网 1v1，两边各一个真人 |

### 经典模式 · 5v5 人机（`de_dust2_lite`）

* **5v5**：玩家 + 每队 4 个 Bot。子弹对队友无效（`friendlyFire` 关闭）。
* **MR12 赛制**：先拿 13 分获胜，最多 24 回合，第 12 回合后换边。
* **回合流程**：8 s 冻结时间（不能移动，可买枪）→ 20 s 购买时间 → 115 s 回合 → 回合结束 5 s 结算。
* **经济**（CS 数值）：
  * 起始 800，上限 16000；胜 3250，靠炸弹获胜 3500；
  * 败方 1400 + 连败 ×500（最多累计 4 连败，上限 3400），埋包成功即使被拆也给 800；
  * 埋包 +300、拆包 +300。
* **C4**：T 携带者进 A/B 点位按住 `E` 3.2 s 埋包，炸弹 40 s 后爆炸；CT 对炸弹按住 `E` 拆包 5 s（有拆弹器）/ 10 s（无）。
* **购买菜单**：17 把武器 + 3 件装备（护甲 650 / 护甲+头盔 1000 / 拆弹器 400，仅 CT）。

### 单挑模式 · 1v3 人机 / 局域网 1v1（`aim_duel_lite`）

* **地图**：约 36 × 51 m——一个屏宽、一条 AWP 长枪线。中央箱子群、两条长边路、两侧 128 u 高台（走楼梯上去，楼梯每级 16 u，正好在 `stepHeight` 之内），整张图 180° 中心对称，所以两边完全公平。没有炸弹点、没有 C4。
* **三阶段武器**（`MODES.duel.phases`）：**只有该阶段白名单里的枪能买**，其余在购买菜单里是灰的（提示「本阶段不可购买」）。

  | 回合 | 阶段 | 能买 | 每回合免费发 |
  |---|---|---|---|
  | 1 – 8 | 手枪局 | 手枪 + 刀 | Glock（T）/ USP（CT） |
  | 9 – 23 | 步枪局 | 手枪 + 步枪 + 刀 | AK-47（T）/ M4A4（CT） |
  | 24 – 33 | 狙击局 | 手枪 + 狙击枪 + 刀 | AWP（两边） |

* **先赢 17 回合获胜**，最多 33 回合（8 + 15 + 10）；单挑局不换边。
* **经济**：起始与上限都是 16000——单挑局里卡你的是阶段白名单，不是钱。冻结 5 s、购买 15 s、回合 90 s、回合结束 4 s。
* **纯消灭**：一方全灭即回合结束；时间到了双方都还有人，按「活人数 → 总血量 → T 判胜」定胜负。
* **单机**：你 1 人打 3 个 Bot（Bot 不买东西，直接拿阶段免费枪）。**局域网**：两边各 1 个真人，没有 Bot。
* 小刀**有效距离 72 单位（≈1.4 m）**，得贴脸挥；挥砍不再被弹药检查吞掉，可以一直挥。

武器表现全部按 CS 数值建模：步枪 AK-47 / M4A4 / M4A1-S / Galil / AWP / SSG08，冲锋枪 MP9 / MAC-10 / P90，手枪 Glock / USP / P250 / Five-seveN / Deagle，霰弹枪 Nova，以及刀、C4（共 17 件）。
每把枪都有**固定可背的弹道图案**（前 10 发的偏移表 + 种子化随机）、独立的头部/胸腹/胃/腿判定、护甲吸收与穿透。

### 地图可读性（雷达 + 世界标签 + 分区染色）

第一版地图是**能用但读不懂**的：几何审计（136 个 brush、311 个连通导航节点、封闭边界，见 `tests/map.spec.ts`）证明它不坏，只是到处长一个样——99.5% 的可行走地板是同一个 `sand` 色调，18 个命名区域里 12 个地板颜色完全相同，7 种墙高、零屋顶，5 个出生点里 4 个正对一面 7.3 m 的空白墙；而唯一的导航提示（雷达）因为一个判据错误画成了一整块深色矩形。三处修复：

* **雷达地板不再看 brush 厚度**。原判据 `brush.size.y <= 48 → 地板`，但四块地面 slab 本身厚 64，于是 117/135 个 brush 被当成墙画成深色 → 雷达变成一块黑板。现在**地板由导航网格铺出来**（`RADAR_FLOOR_HALF = 132`，`map.nav` 的 311 个节点各铺一块方块，用**同一条 path 一次性 `fill()`** 做并集，所以重叠处不会叠亮），**墙只画厚度 ≥ 112 单位（一人高）的 brush**（`RADAR_WALL_MIN_THICK`），楼梯、木箱、B 车这些矮件交给导航填充。
* **世界自己标注地名**（`src/render/Signs.ts`）。此前只有雷达有 callout 标签，还被上面的 bug 挡着，且只画前 14 个（共 21 个）。现在 21 个全上雷达（26 px 防重叠框，挤不下就跳过而不是截断），并且**在地图里也立起牌子**：地板地名 300 单位、A/B 点位大字 420 单位（琥珀色）、两队出生点墙面挂牌 320 单位（`T SPAWN` / `CT SPAWN`，从出生点沿朝向用 AABB slab 射线打最近墙面，打不到就不立，避免悬空牌）。全部合并成**一个 mesh、一张 256 px canvas 图集、1 个 draw call**（`renderOrder = 2`，在地图之上、角色轮廓之下），不参与光照。
* **分区染色跟着地图走**（`MapData.paint`）。用**贴花 quad**而不是改 brush 色调：brush 的 `tint` 是绝对颜色且按 `材质|色调` 分桶（多一个地面色就多一个 draw call），要换色得把 4 块巨大地面 slab 拆成区块（漏一块就是地板上的一个洞），而垫一层薄 brush 又会把真实地板抬高 2 单位并影响 `floorTopAt` 与导航断言。贴花不碰 brush、不碰烘焙导航、不碰碰撞——回归测试直接断言 dust2 的 `map.brushes.length === 136`。染色区域现在由**每张地图自己声明**：dust2 用遗留的 `SIGN_ZONES`（7 个区：出生点 / Mid / LongA / Tunnels / A 点 / B 点），单挑小图声明自己的 9 个区（每个可行走区域一块，两条楼梯故意不刷——一块平板贴花跟不上 8 级踏面）。以前是 dust2 的坐标被硬刷到单挑图上，等于在小图地板上浇了几块不相干的色斑。

## 3. 局域网 1v1（主机在浏览器里当服务器）

浏览器标签页**不能监听端口**，所以没有「先起一个服务器进程再让浏览器连」这条路。这里的做法是：**主机那个标签页就是权威服务器**。

```text
主机浏览器：      128 Hz 的 Match（T 侧） + LanSession(host)
                            │  ws://主机IP:5175/lan?room=duel&role=host
                    server/lan-relay.mjs（转发，不懂游戏）
                            │  ws://主机IP:5175/lan?room=duel&role=guest
客机浏览器：      Mirror Match（只驱动自己的身体，CT 侧） + LanSession(guest)
```

* **怎么用**：主机点「创建房间」（或在启动器里双击即玩后从菜单进），把控制台/启动器打印的 `http://<局域网IP>:5174/?join=1` 发给朋友；朋友在**同一个 WiFi** 下打开它，页面上会显示 `主机 · 已连接`。也可以从菜单点「加入房间」手填 `192.168.1.23:5174`（写 5174 就代表「它旁边的中继」，即 5175；写别的端口就当中继端口）。
* **中继很简单**：`server/lan-relay.mjs` 是零依赖的裸 Node 脚本（手写 RFC 6455 握手与帧编解码，`node server/lan-relay.mjs`），只做房间配对的搬字节，**不含任何游戏逻辑**。`GET /status` 能看到房间列表。启动器会自动拉起它，也可以自己开。
* **谁说了算**：快照（位置/朝向，20 Hz，二进制，`NET_PROTOCOL_VERSION = 1`）只由主机发；客机是 `mirror: true` 的 Match，**只跑自己的移动**，别人的身体完全由快照覆盖（本地再模拟一遍会打架），伤害一律由主机判定。回合、比分、血量、钱走另一条 JSON 状态通道（10 Hz）。
* **客机不做预测回滚**：它 100 ms 插值缓冲显示主机世界，输入以 30 Hz 上行。所以移动是「跟手但有一点延迟」，不是 CS 那种预测+回滚的瞬时手感（见第 11 节）。
* **阵营固定**：主机永远 T（下半场不换边），客机永远 CT；客机的准心开火只有画面反馈，判定在主机那边。断线/被顶号时 HUD 上方会显示 `主机 · 已断开`。
* 想验证协议而不是玩游戏：`node server/lan-relay-check.mjs`（自起一个中继，跑一遍握手、配对、二进制透明、顶号、掉线，12 项全绿）。

## 4. 「CS 手感」是怎么落地的

计划里拆出的 7 个要素，逐条对应实现：

| # | 要素 | 实现 |
|---|---|---|
| 1 | **移动** | 自研 Quake 系运动模型：地速 250、走 130、蹲 85、空中加速保留但限速 30、连跳保速；1 米 = 52.49 单位，重力 800、起跳冲量 268.3 |
| 2 | **枪口稳定** | 速度→散布曲线（`computeInaccuracy`：移动项按 `(speed/250)^1.25`，空中锥角独立给定），必须急停才准 |
| 3 | **弹道** | 每把枪 30 发固定偏移表 + 种子化伪随机，前 10 发可背 |
| 4 | **命中判定** | 头 / 胸腹 / 胃 / 腿分离胶囊体；腿和无头盔爆头无视护甲 |
| 5 | **反馈** | 枪口火焰、抛壳、弹孔贴花（上限 192 个）、命中提示音、击杀播报、血迹、曳光弹、着弹火花、尘土、**擦耳弹啸**（`whizzBy`：路径离耳朵 64 单位以内的子弹发 `whizz` 事件，音量随最近距离缩放） |
| 6 | **节奏** | 完整回合计时器 + 经济 + 买枪菜单 + 炸弹攻防 |
| 7 | **视角** | 相机层可叠加：走路摆动（bob）、开枪后坐视角偏移（punch，水平 ±0.5 / 垂直 ±0.45 弧度）、落地下沉、开镜变焦 |

**明确不做**：自动回血、无限冲刺、载具、瞄准镜呼吸。

### 三个把「手感」做对的细节

* **急停是有代价的**：`stopSpeed = 80`，摩擦 5.2。这个数字很关键——摩擦的每 tick 下限是 `80 × 5.2 × dt`，必须小于蹲行加速 `5.5 × 85 × dt`，否则蹲姿玩家会被摩擦钉在原地（本项目真的踩过这个坑，见 §7）。同时 250 → 0 刹停约 0.4 s，仍然「脆」。
* **连跳保速不增益**：落地那一 tick 的摩擦亏损（250 u/s 时 10.2）≈ 地面加速补回（10.7），加速度在 250 处夹紧，所以连跳恰好停在 250；把落地摩擦清零会产生 surf 式 400+ u/s 的失控。
* **视角抖动不进准心**：`punch` 只作用于相机，`aimDirection()` 才把它叠加进射击方向——否则后坐会永久污染 `state.yaw`（人机对战里 Bot 就是这么治好的）。

## 5. Bot AI

* 难度 4 档，每档只调 4 个参数：`reactionTime`（反应时间）、`aimError`（瞄准误差）、`sprayControl`（压枪）、`preaimQuality`（预瞄质量）。每个 Bot 出生时再乘一个 0.8–1.2 的随机系数，所以同一档也有强弱差异。
* **感知**：射线可见性检查 + 目标记忆 6 s（记住最后已知位置，会追过去）+ 听觉（脚步、枪声、埋包/拆包声）。受到攻击会撤退。
* **目标选择**：五级级联——1) 任务（埋/拆/守点）2) 交火 3) 保命 4) 调查声音 5) 推进/守点。埋包后 CT 转为「retake」、T 转为「守炸弹」。
* **导航**：`de_dust2_lite` 手工烘焙的 **309 个节点**导航图（含 A 大、B 洞、中路、猫道、A/B 点内部节点），`findPath` + 路径平滑 + 卡住检测（连续 24 tick 位移 < 0.5 单位就尝试左右探路脱困，并重挂路径）。
* **开火条件**（`shouldFire`）是严格的：弹药/换弹/开镜时间检查 → 反应时间已过 → 有可见敌人 → 瞄准角误差在胸宽锥角内 → 散布不超过阈值 → 在有效射程内 → 伤害 > 0 → 不误伤队友。所以 Bot 不是「看见就突突」，而是必须真正瞄上。
* **身体分离**：Bot 会朝共享的目标节点收拢，所以每 tick 有一遍 `separatePlayers`——水平距离小于两个半径的存活角色互相推开（单 tick 最多 8 单位，会把角色推进墙里的推动整条丢弃，玩家永不被推）。否则一整队会叠在同一个坐标上。
* **单挑模式没有炸弹点**：Bot 的任务退化成 `hunt`——直接以最近敌人的导航节点为目标，所以它们会主动压过来，不会因为找不到 A/B 点位而站着不动（这是小图刚接进来时真实踩过的坑）。

## 6. 性能报告

全部数字在本机（Node 24 / Windows）实测，脚本可复现：`pnpm vitest run tests/perf.spec.ts`。

### 模拟（逻辑）

| 指标 | 预算 | 实测（两次独立运行） |
|---|---|---|
| 10 人满员回合 `Match.tick` 平均 | < 0.60 ms | **0.38 – 0.53 ms**（p50 0.32–0.48 / p95 0.69–0.94 / max 2.27–15.2，2560 样本） |
| 有开火的那一 tick 平均 | — | **0.70 – 1.09 ms**（8–18/2560 tick 有射击，p50 0.54–0.92） |
| 单人 `stepMovement` | — | **0.0016 – 0.0026 ms**；外推 10 人 × 128 Hz = **0.016 – 0.026 ms/tick** |
| `nav.findPath`（CT 出生点 → A 点） | — | **0.74 – 1.03 ms**（p95 1.15–1.37），只在换目标时调用，不是每 tick |
| `nav.nearestNode` | — | **0.0006 – 0.0013 ms** |

一个回合 20 s 窗口内：8–18 发子弹、5–13 次命中、2560 tick。

**结论**：模拟预算 0.6 ms/tick（128 Hz 下占用 7.7% 的一帧）有充足余量——满员回合均值 0.38–0.53 ms，开火帧 0.70–1.09 ms，导航寻路不在热路径上。

### 渲染

渲染帧率无法在无浏览器环境自动测量（没有 Playwright），预算按计划设为：**draw calls < 80、三角形 < 300k**。
地图几何按 `(材质, 色调)` 合批（`MapGeometry.ts`：约 140 个轴对齐盒子合成十余个 mesh），天空是一个 9000 半径的球面。
可见层另有：**角色**（3 个 `InstancedMesh`：身体 / 尸体 / 队伍色轮廓，16 个槽位）、**第一人称武器**（独立 `Scene` + `clearDepth` 的第二遍渲染；枪在**相机空间**建模，用的是一台只跟世界相机同步 `fov/aspect/near/far` 的独立相机，否则枪会被画到地图原点）、**世界标签与分区贴花**（1 个合并 mesh、1 张图集）；弹孔/血迹贴花上限 192。
在游戏里按 `F3` 或加 `?stats=1` 可看到实时的 `drawCalls / triangles / mapDrawCalls / mapTriangles / programs / textures`。

## 7. 开发中修掉的真实 bug（都有回归测试）

手感类项目的 bug 往往表现为「说不出来哪里不对」，这几条是写 `tests/movement.spec.ts` 时被 15 条物理测试逼出来的：

1. **蹲行走不动**：摩擦的每 tick 下限 `stopSpeed(100) × 5.2 × dt = 4.06` 大于蹲行加速 `5.5 × 85 × dt = 3.65`，速度被钉在 3.65 u/s——蹲着移动 24 tick 只前进 0.57 单位。改成 CS:GO 的 `stopSpeed = 80` 后正常。同一条 bug 也解释了 Bot 在狭路「踱步」的怪现象。
2. **落地吸附把玩家瞬移到天花板顶面**：`sweepExpanded` 在扫描起点就已重叠时返回 `hit=true, fraction=0, normal=(0,1,0)`，地面解算把它当「踩到地面」，于是把脚底吸到那块刷子的**顶面**——低矮天花板下实测 `y` 从 0 跳到 400，玩家站到了天花板上。加了 `GROUND_SNAP_MAX_RISE = 1.0` 上限。
3. **连跳掉速到比走路还慢**：落地 tick 除摩擦外还乘 `vel *= 0.94`，每跳净亏 15 u/s，空中 30 u/s 的加速上限补不回来，实测 3 秒跳跑峰值只有 52.7 u/s。删掉后连跳稳定在 250。
4. **Bot 不开枪**（三个独立根因，都影响人机对战的可玩性）：
   * 没有任何代码把 `cmd.yaw/pitch` 写进 `state.yaw/pitch`（只有相机在动），于是所有 Bot 的瞄准方向永远停在出生角，且后坐（punch）永不衰减、永久污染准心 —— 修复后 Bot 才真正「转身面朝敌人」。
   * 所有 Bot 共用同一个 `InputCommand` 对象，`think` 只写自己决定改的字段，于是每 tick 最后一个 Bot 决定了全队的按键和视角；`shouldFire` 拿 `cmd.yaw` 做夹角检查时量到的是别人的准心 —— 改为每个 Bot 一个 command 对象。
   * 卡住计数器写反了（移动时累加、被挡住时清零），Bot 贴着墙永远报告 `stuck=0`，再加「脱困时只按一侧方向」被转向逻辑的另一侧抵消，会出现 `forward+left+right` 且速度为 0 的永久冻结 —— 两处都修了。
   * 另外：走路脚步声每 tick 触发「去调查声音」，导致埋包后的 CT 全队 40 s 都不去拆包 —— 调查分支现在只在「不需要移动的任务」上生效。
5. **看不到敌人、看不到手里的枪**（用户实测反馈，两个独立根因）：
   * 角色与武器**根本没有渲染代码**：`engine.ts` 只渲染地图、VFX 和 HUD，玩家/机器人没有任何可见几何 —— 雷达上的点就是全部可见信息。补上 `render/Characters.ts`（3 个 `InstancedMesh`：身体、尸体、轮廓）+ `render/ViewModel.ts`（第一人称武器，独立 `Scene` + `clearDepth()` 第二遍渲染）。
   * 第一人称武器**用世界相机渲染**：模型是在相机空间建模的（`x ≈ +7` 右、`y ≈ -6` 下、`z ≈ -14…-44` 前），拿世界相机画等于把它放回地图坐标原点附近（开局时离玩家 2400+ 单位，且 `y = -6` 埋在地面里）。现在 `ViewModel` 自带一台只同步投影参数（`fov/aspect/near/far`）的正交平移相机；回归测试断言 `renderCamera !== worldCamera`、相机位置为原点、枪的包围盒中心投影落在屏幕内且在近裁剪面之前。
6. **按键误触浏览器快捷键**（用户实测反馈）：蹲伏绑在 `Ctrl` 上，而蹲着走位等于一直按住 `Ctrl` 按 `WASD` —— `Ctrl+W` 关标签页、`Ctrl+D` 收藏、`Ctrl+R` 刷新，这些都是**页面无法拦截**的。另外 `InputSystem` 从未调用 `preventDefault()`：`Space`/方向键会滚动页面、`Tab` 会走焦点环。现在蹲伏改**左 `Alt`**（备选 `C`，`DEFAULT_BINDINGS` 里没有任何 `Control*`，测试断言这一点），并对 `BROWSER_HOGGED_KEYS`（含自动重复）统一 `preventDefault()`，输入框目标除外。
7. **走路时手上的枪在抖、刀挥不动、捡不到枪**（用户实测反馈，三个独立根因）：
   * **枪抖**：`bobFreq` 的语义是「每秒几个完整步」，但视角模型把它当成每帧相位增量用，`9.2` 实际是 ≈14 Hz 的高频振动 —— 相机上看不出来（`bobY × 0.35` 只有一两单位），而枪在眼前 30–80 单位处被放大约 30 倍，于是一走路枪就「嗡嗡抖」。改成 `bobFreq = 1.9`（冲刺 ≈2.95 Hz、走 ≈2.0 Hz），并给振幅加了平滑（`bobSmooth = 14`，起步/刹车不再瞬间拉满）。`tests/camera.spec.ts`（新增 3 条）锁住两秒内的过零次数与振幅包络。
   * **刀挥不动**：① `handleFire` 里 `if (def.slot === 'knife') return;` 直接吞掉了近战开火；② 即使放行，`tryFire` 的通用弹药闸门也会让刀（`magazine: 1 / reserve: 0 / reloadTime: 0`）挥一次就永久哑火。现在近战跳过弹药检查与扣减，仍受 `rpm` 限制，并补了挥砍反馈（相机 roll + 视角模型横扫），弹道上 `KNIFE` 是 40 伤害 / 0.85 穿甲。
   * **捡不到枪**：尸体把主武器和副武器丢在**同一个坐标**上，站在上面的玩家与两把枪距离都是 0，原来的「更近就换」在平局时选到了较远槽位的那把（实测 `E` 换到的是别人的副武器）。现在平局按用途排序：先「能填进空槽」的，再「与手上同槽位」的，最后取最新掉落的。
8. **刀无视攻击距离，隔着半张图也能砍死人**（用户实测反馈）：近战走的是同一条 hitscan，但 `fireShot` 没给近战传 `maxRange`，于是回落到 `COMBAT.maxRange = 8192`（= 半张地图），站着不动朝对面挥一下就能触发命中判定。现在近战固定 `COMBAT.meleeRange = 72`（≈1.4 m），`tests/ballistics.spec.ts` 里有一条回归：距离 40 单位命中，×4 距离必须不命中（把这一行注释掉就会红）。主菜单底部与 HUD 也写明了「匕首有效距离 1.4 m」。
9. **单挑小图的地板被刷上了 dust2 的分区色**：分区染色表（`SIGN_ZONES`）原本写死在渲染层里，坐标全是 dust2 的（x 到 2145、z 到 2855），而单挑小图只有 2112 × 2880，于是那 7 块半透明贴花在**完全不相干的位置**浇在小图地板上。现在染色区域由**地图数据自己声明**（`MapData.paint`），dust2 保留遗留表、单挑图声明自己的 9 个区，回归测试断言「每条染色都在自己那张图的墙体之内、且与 180° 镜像严格配对」。

## 10. 已知限制

* **投掷物（闪光/烟雾/HE）未实现**：`weaponDefs` 里没有手雷定义，买枪菜单的投掷物栏是空的，`slot4/5` 没有内容。这是当前最明显的缺口。
* **局域网 1v1 能玩，公网联机没有**：没有匹配服务、没有 NAT 穿透、没有独立部署的服务器——只有「同一个局域网 + 手动填主机 IP」。主机那个标签页必须一直开着（它同时是权威服务器和玩家），关掉就断线。
* **客机没有客户端预测/回滚**：它只是主机世界的一面镜子（20 Hz 快照 + 100 ms 插值缓冲，输入 30 Hz 上行），所以是「跟手但有一点延迟」，没有 CS 那种本地即时命中反馈；伤害一律由主机判定，客机开火只有画面反馈。局域网 1–3 ms 的延迟下看不出来，公网下会明显（`src/net/Prediction.ts` 里的 `PredictedWorld` / `Reconciler` 目前还是空接口）。
* **房间里不能中途加入或旁观**：房间固定 1v1（一个 host 一个 guest），第二个客机顶掉第一个，没有断线重连恢复比分。
* **单挑局不换边**：主机永远 T、客机永远 CT（单机时你是 T）；小图是 180° 中心对称的，所以公平性没问题，但不像 CS 那样换边。
* **Bot 之间只做「推开」而不是真正的身体阻挡**：`Match.separatePlayers` 每 tick 把水平距离小于两个半径的存活角色各推开一半（单 tick 上限 8 单位，会把角色推进墙里的推动整条丢弃，玩家本人永不被推），所以不会再看到几个人叠在同一个坐标上，但这仍不是 CS 那种「贴住对方就过不去」的硬阻挡，拥挤时会有轻微推挤感。
* **导航图有两处绕路**：CT 出生点北墙附近的车道节点被墙带吞掉（`nearestNode` 判为实心而丢弃），导致 CT 去 B 点会多绕一段。
* **地图仍然没有屋顶，出生点朝向也没改**：这次修的是「读不懂」（雷达地板、世界地名标签、分区染色），没动结构和尺寸——墙只有 7 种高度、头顶空空，所以从高处看依然空旷；5 个出生点里 4 个仍然正对空白墙，只是那面墙上现在挂了 `T SPAWN` / `CT SPAWN` 牌子。
* **贴图管线是死代码**：`src/world/materials.ts`（255 行）与 `src/world/textures.ts`（1259 行）没有任何模块 import，地图实际用 `MapGeometry` 自己的 `MeshStandardMaterial`（纯色 + 顶点明暗）。复活它前要先统一色调语义：那里的 `tint` 是**绝对颜色**而不是乘数，照直接上去会把地图压暗。
* **T 队 AI 偏「正面强冲」**：Bot 会集体压 A 大被 CT 架枪团灭，战术多样性不足（平衡问题，不是故障）。
* **渲染性能与画面只能人工确认**：自动化环境里没有 GPU/浏览器，`drawCalls`、三角形数、贴花上限都需要玩家按 `F3` 自查。
* **左 `Alt` 蹲伏的代价**：`Alt+Tab` 是操作系统级组合，页面拦不住，所以蹲着按 `Tab` 看记分板偶尔会把窗口切出去（`C` 作为备用蹲伏键就是给这种情况留的）。
* **启动器只在 Windows 上可用**：`launcher\play.ps1` 是给 Windows PowerShell 5.1 写的脚本，三个 `.cmd` 入口靠双击使用；macOS / Linux 直接用 `pnpm dev`（见第 0 节）。
